# RTX 5080 主机运行说明

正式主机是用户家中的 RTX 5080，操作系统、显存占用、驱动和 Python 尚未检查。当前准备主机为 Windows、GT 710 2GB，不安装 GPU 训练环境。

## 先运行不需要依赖的准备步骤

将本项目复制或从已配置的 GitHub 仓库拉取到主机，进入 `research/medical-vlm-hierarchy`：

```powershell
python preflight.py --output outputs/home-preflight-01
python -m unittest -v test_core.py
python prepare_ham.py --output outputs/home-ham-01 --download-images
python prepare_pad.py --output outputs/home-pad-01
```

输出目录不能已存在，重跑使用新编号，防止覆盖历史。最后一个命令从 Harvard 官方源下载两个原图 ZIP，约 2.77GB，逐个验证 MD5；它不解压原图、不自动接受任何另需账户确认的协议，也不会启动模型推理。

`preflight.py` 和 HAM 下载/分组工具仅依赖 Python 标准库。主数据、split 和逐样本缓存只在本机保留，不上传 GitHub。

## GPU 环境原则

建议单独建立 Python 3.11 环境。使用支持 Blackwell 的 PyTorch 与 CUDA 12.8 或更新的兼容构建；不能照搬旧项目的 CUDA 11.x 环境。依据：[PyTorch 2.7 Blackwell 支持说明](https://pytorch.org/blog/pytorch-2-7/)、[官方安装选择器](https://pytorch.org/get-started/locally/)。精确 torch/torchvision/open_clip/transformers 版本在实际 5080 主机验证后锁定，目前不声称已完成兼容性测试。

后续安装在独立环境中完成，先运行 `torch.cuda.is_available()`，检查设备名、编译架构与一次实际矩阵运算，随后用 batch=8 做 224 输入的模型小批次测速。记录峰值显存、CUDA wheel、驱动和耗时，再决定 batch；不要仅凭 nvidia-smi 显示 CUDA 版本判断 PyTorch 可用。

当前已经实现元数据审计、组级划分、层级参考基线和风险/效用计算。图像内容去重、树的医学依据核对、正式特征提取、完整基线实验尚未完成，不应跳过数据审计直接调方法。

## 图像审计与冻结特征入口

原图解压到独立 `data/` 目录后，安装轻量审计依赖再运行。以下路径为示例，按实际输出目录替换：

```powershell
python -m pip install -r requirements-audit.txt
python audit_images.py --images data/HAM10000 --split outputs/home-ham-01/split_seed17.csv --output outputs/home-ham-image-audit-01
```

审计工具不会解压 ZIP；只扫描 JPG/JPEG/PNG。不允许多个目录有同名图像。缺图/坏图会标记不完整并阻止特征输入；近重复只列候选，必须审阅后再冻结正式数据协议。PAD 必须采用最新保守分组：共享 raw lesion_id 的患者整体不跨集合。不要用旧失败版本的划分。

GPU 环境安装好后先跑 `python check_gpu.py --output outputs/home-gpu-check-01`。通过 CUDA 小矩阵检查也不代表模型兼容性验证完成。

冻结图像特征的实际接口如下；权重与配置需从官方固定 revision 下载，SHA256 使用实际文件校验结果：

```powershell
python extract_features.py --model clip --audit outputs/home-ham-image-audit-01 --weights checkpoints/ViT-B-16.pt --weights-sha256 <实际SHA256> --revision <官方权重标识> --device cuda --batch-size 8 --output outputs/home-clip-cache-01
python extract_features.py --model biomedclip --audit outputs/home-ham-image-audit-01 --weights checkpoints/open_clip_pytorch_model.bin --weights-sha256 <实际SHA256> --model-config checkpoints/open_clip_config.json --revision 9f341de24bfb00180f1b847274256e9b65a3a32e --device cuda --batch-size 8 --output outputs/home-biomedclip-cache-01
```

尖括号为必须替换的说明，不是可原样运行的 PowerShell 参数。BiomedCLIP 采用官方本地加载配方，调用版本敏感的 OpenCLIP 配置接口；本机没有 GPU 依赖，尚未完成模型推理测试。即使权重在本地，HF 文本编码器配置仍可能需要预先缓存。正式环境通过小样本加载后应保存 `pip freeze` 并锁定版本，再执行全量提取。

每次缓存保存模型 revision、权重/配置/清单/特征文件哈希、预处理、依赖版本、耗时、峰值显存。失败写入 cache.json，不静默退到 CPU。缓存 FP32、L2 归一化，本轮不启用混合精度或训练。
