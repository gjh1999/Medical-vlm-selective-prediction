# RTX 5080 主机运行说明

正式主机是用户家中的 RTX 5080，操作系统、显存占用、驱动和 Python 尚未检查。当前准备主机为 Windows、GT 710 2GB，不安装 GPU 训练环境。

## 先运行不需要依赖的准备步骤

将本项目复制或从已配置的 GitHub 仓库拉取到主机，进入 `research/medical-vlm-hierarchy`：

```powershell
python preflight.py --output outputs/home-preflight-01
python -m unittest -v test_core.py
python prepare_ham.py --output outputs/home-ham-01 --download-images
python prepare_pad.py --output outputs/home-pad-01
```

重跑请使用新的输出目录。`prepare_ham.py --download-images` 从 Harvard 下载并校验两份原图 ZIP，共约 2.77 GB。准备机已有校验通过的压缩包，也可以复制到目标机，复核哈希后解压。两份文件的 MD5 依次为 `4639bfa73ab251610530a97c898e6e46` 和 `da43d6cc50f6613013be07e8986b384b`。PAD 命令只获取元数据。

`preflight.py` 和 HAM 下载/分组工具仅依赖 Python 标准库。主数据、split 和逐样本缓存只在本机保留，不上传 GitHub。

## GPU 环境原则

建议单独建立 Python 3.11 环境。使用支持 Blackwell 的 PyTorch 与 CUDA 12.8 或更新的兼容构建；不能照搬旧项目的 CUDA 11.x 环境。依据：[PyTorch 2.7 Blackwell 支持说明](https://pytorch.org/blog/pytorch-2-7/)、[官方安装选择器](https://pytorch.org/get-started/locally/)。精确 torch/torchvision/open_clip/transformers 版本在实际 5080 主机验证后锁定，目前不声称已完成兼容性测试。

后续安装在独立环境中完成，先运行 `torch.cuda.is_available()`，检查设备名、编译架构与一次实际矩阵运算，随后用 batch=8 做 224 输入的模型小批次测速。记录峰值显存、CUDA wheel、驱动和耗时，再决定 batch；不要仅凭 nvidia-smi 显示 CUDA 版本判断 PyTorch 可用。

准备机已完成双库图像审计、HAM v1.4 组级划分、双骨干开发集验证、层级基线与风险和效用计算。疾病类别树仍是研究草案，正式特征提取、完整基线实验与目标机性能测量待执行。

## 图像审计与冻结特征入口

原图解压到独立 `data/` 目录后，安装轻量审计依赖再运行。以下路径为示例，按实际输出目录替换：

```powershell
python -m pip install -r requirements-audit.txt
python -m zipfile -e outputs/home-ham-01/HAM10000_images_part_1.zip data/HAM10000/part1
python -m zipfile -e outputs/home-ham-01/HAM10000_images_part_2.zip data/HAM10000/part2
python -m pip install numpy opencv-python-headless
python prepare_ham_formal.py --images data/HAM10000 --source-dir outputs/home-ham-01 --pair-dir outputs/home-ham-01 --workers 3 --output outputs/home-ham-v14-01
$audit = 'outputs/home-ham-v14-01/audit'
```

当前正式 HAM 划分为 v1.4。原图及作者两份 CSV 就绪后，`prepare_ham_formal.py` 可离线完成全部阶段。新输出中的 `splits/`、`audit/`、`sensitivity/` 分别用于正式划分、特征输入和保守敏感性分析。`run.json` 记录各阶段状态与用时。程序会核对最终 5 对几何关联的可移植哈希。准备机用 Pillow 13.0.0、NumPy 2.5.4 和 OpenCV 5.1.0 复核；目标平台的三份 split CSV 哈希可与[已验证输出](reports/E00-ham-scene-splits-01.json)逐一对照。

PAD 可用 `python prepare_pad_images.py --split-dir outputs/home-pad-01 --output outputs/home-pad-images-01` 下载原站 ZIP。已持有原版 ZIP 时增加 `--archives 本地目录`。Mendeley 此次返回错误正文，准备机另行运行 `audit_pad_mirrors.py`，逐张核对两个固定镜像及官方病例元数据。需要 PyArrow，命令及结果见[实验记录](实验记录.md)。外部分析同时报告涉及相同像素、不同标签的组级敏感性结果。

GPU 环境安装好后先跑 `python check_gpu.py --output outputs/home-gpu-check-01`。通过 CUDA 小矩阵检查也不代表模型兼容性验证完成。

OpenAI ViT-B/16 使用官方加载器和配套预处理。已安装适配目标机的 torch 和 torchvision 后，运行以下命令。用目标机本地审计生成的 manifest，里面的绝对图像路径须指向目标机文件。

```powershell
python -m pip install git+https://github.com/openai/CLIP.git@d05afc436d78f1c48dc0dbf8e5980a9d471f35f6
python prepare_openai_clip.py --output outputs/home-openai-weights-01
python extract_features.py --model clip --audit $audit --weights outputs/home-openai-weights-01/ViT-B-16.pt --weights-sha256 5806e77cd80f8b59890b7e101eabd078d9fb84e6937f9e85e4ecb61988df416f --revision OpenAI-ViT-B-16 --device cuda --batch-size 8 --smoke-only --prompt-config configs/ham-dev-pilot-v1.json --output outputs/home-clip-smoke-01
python verify_clip_smoke.py --audit $audit --smoke outputs/home-clip-smoke-01 --weights outputs/home-openai-weights-01/ViT-B-16.pt --output outputs/home-clip-reference-01
```

`--smoke-only` 按图像 ID 顺序取最多一批训练集代表图，在 `cache.json` 中标为 `smoke_complete`。核对 QuickGELU、FP32、输出形状与耗时。通过目标机验收后，全量提取时去掉该参数并换用新的输出目录。近重复候选的审阅状态随缓存保留。BiomedCLIP 仍使用 OpenCLIP 与固定配置。

```powershell
python prepare_biomedclip.py --output outputs/home-biomed-weights-01
$env:HF_HUB_OFFLINE='1'
python extract_features.py --model biomedclip --audit $audit --weights outputs/home-biomed-weights-01/open_clip_pytorch_model.bin --weights-sha256 52cc993c5c5ff962bd0c60931874bc001e7e9b41666a385530f4a036294576be --model-config outputs/home-biomed-weights-01/open_clip_config.json --revision 9f341de24bfb00180f1b847274256e9b65a3a32e --device cuda --batch-size 8 --smoke-only --prompt-config configs/ham-dev-pilot-v1.json --output outputs/home-biomedclip-smoke-01
```

下载脚本同时检查原版模型的 SHA256 和分词器、文本配置的上游 Git blob 哈希。准备机实测 OpenCLIP 2.23.0、timm 0.9.16、transformers 4.57.6；模型卡的 transformers 版本为 4.35.2。两个冻结模型均已在 CPU 离线完成图文推理。正式环境通过小样本加载后保存 `pip freeze` 并锁定版本。[作者模型卡](https://huggingface.co/microsoft/BiomedCLIP-PubMedBERT_256-vit_base_patch16_224/blob/9f341de24bfb00180f1b847274256e9b65a3a32e/README.md)

两套图文缓存都用逐图、逐提示的独立前向复核，比较全部 8 × 18 个 logits。准备机两个骨干均通过，5080 实测时复用同一命令和容差。

```powershell
python verify_prompt_cache.py --audit $audit --cache outputs/home-clip-smoke-01 --prompt-config configs/ham-dev-pilot-v1.json --weights outputs/home-openai-weights-01/ViT-B-16.pt --output outputs/home-clip-text-reference-01
python verify_prompt_cache.py --audit $audit --cache outputs/home-biomedclip-smoke-01 --prompt-config configs/ham-dev-pilot-v1.json --weights outputs/home-biomed-weights-01/open_clip_pytorch_model.bin --model-config outputs/home-biomed-weights-01/open_clip_config.json --output outputs/home-biomedclip-text-reference-01
```

每次缓存保存模型 revision、权重/配置/清单/特征文件哈希、预处理、依赖版本、耗时、峰值显存。失败写入 cache.json，不静默退到 CPU。缓存 FP32、L2 归一化，本轮不启用混合精度或训练。

`--prompt-config` 从给定配置读取类别树、节点名称和提示模板。图像组始终取自当前审计清单。命令中的固定模板和名称沿用开发小试，输出 `text_features.npy` 的轴为模板、节点、特征维度。`cache.json` 的 `text` 字段记录节点顺序、提示、配置与特征哈希、检查点原始 logit scale 和文本耗时。只需图像特征时可省略该参数。
