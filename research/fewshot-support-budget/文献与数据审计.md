# 文献与数据审计

更新：2026-11-17。证据级别区分：全文/代码已核对、摘要已核对、待核实。初轮定向检索，不是系统综述。检索词包括 few-shot medical segmentation support selection、annotation budget、support mask quality、in-context segmentation。

## 最接近的原始工作

| 工作与原始来源 | 本轮确认内容 | 对本项目的影响 |
| --- | --- | --- |
| [UniverSeg，ICCV 2023](https://openaccess.thecvf.com/content/ICCV2023/papers/Butoi_UniverSeg_Universal_Medical_Image_Segmentation_ICCV_2023_paper.pdf)，[官方代码](https://github.com/JJGO/UniverSeg) | 已读官方 README、模型文件和论文相关段落；免训练支持集条件分割，原文已研究支持数与随机波动 | 冻结基线；单纯画 shot 曲线不是创新 |
| [Context Matters，arXiv:2608.05333v1](https://arxiv.org/html/2608.05333v1) | 已核对 HTML 方法及局限：MultiverSeg + DINOv3 图像检索、失败预测；作者说明选择不使用掩膜，限于单一模型/编码器与固定划分 | 直接重合，必须纳入强基线；加失败检测也不能直接称创新。预算下的标签修正是候选区别，尚非已证实空白 |
| [MultiverSeg，ICCV 2025](https://openaccess.thecvf.com/content/ICCV2025/papers/Wong_MultiverSeg_Scalable_Interactive_Segmentation_of_Biomedical_Imaging_Datasets_with_In-Context_ICCV_2025_paper.pdf) | 已核对 context quality/bootstrapping 相关段落，涉及不完美上下文掩膜及交互修正 | “支持标签噪声有害”本身已有研究；后期需跨模型验证，并计入交互成本 |
| [How to select slices for annotation…，PMLR 301，2026](https://proceedings.mlr.press/v301/zhang26a.html) | 摘要报告固定预算下，更多体积、每体积较少切片通常更好；其设置下无监督选样并不优于随机/等间隔 | 患者覆盖与切片数不能混同，保留患者分散随机与等间隔基线。其训练式结论不能直接搬到冻结 ICL |
| [Benchmarking Foundation and Large Language Models for Few-Shot Medical Image Segmentation，2026](https://arxiv.org/abs/2607.27856) | 题录/摘要确认，未完成全文协议审计 | 扩展基线前核对任务定义、支持预算和提示信息 |
| [Visual prompt selection for in-context learning segmentation，2024](https://arxiv.org/abs/2407.10233) | 从 Context Matters 参考文献定位，本文未完成阅读全文 | 补查通用视觉选样；去冗余、质量评分、选择器都不能未经对照视作新方法 |

结论：本方向有起步价值，但选样本身高度拥挤。研究价值应由“什么预算条件下应该多标、何时应该修正，以及能否不看真值作出决定”的实测证据支撑。尚未验证这种分配策略优于固定比例或随机。

## 模型与许可

本地源码审计成功固定 UniverSeg commit：`833a0c34c65e38d675e21bd48ddec6797cc03259`。

- 官方输入为单通道、128×128，图像数值归一化到 [0,1]；支持图像与掩膜张量为 `(B,S,1,H,W)`。小病灶和细边界的下采样损失需要单列分析。
- 代码许可 Apache-2.0；权重许可单列 OpenRAIL++-M，官方 README 指定研究用途。已保存权重许可文件，未下载权重。
- 上游依赖未固定版本，包括 torch、numpy、Pillow、einops、pydantic、nibabel；实际组合需在目标机核验。
- `example_data/wbc.py` 与 `example_data/oasis.py` 在官方树中存在，本轮尚未下载其数据。不能用“示例可见”替代数据许可核验。
- 权重入口可从固定版本 `universeg/model.py` 追溯；权重 SHA256、CUDA 兼容性、吞吐和显存均未知。

## 2026-11-18 已核对的可用单位与最近方法

- WBC 示例在固定源码中按文件名排序配对 BMP 与 PNG，以种子 42 打乱图像索引，默认取前 70% 为支持池。加载器没有使用患者字段。数据作者给出的 JTSC、CV 两来源分别有 300 张和 100 张图像，由此推算支持/测试为 210/90 和 70/30 张。本轮未清点本地原图，独立患者数未知。作者列有使用时的致谢与引用要求，仓库标记 GPL-3.0，第三方图像再分发权限待核。WBC 当前用于管线验证。[固定版加载器](https://github.com/JJGO/UniverSeg/blob/833a0c34c65e38d675e21bd48ddec6797cc03259/example_data/wbc.py) · [数据作者说明](https://github.com/zxaoyou/segmentation_WBC)
- ACDC 官方描述 150 位患者、五亚组各 30 人，每个病例有两个标注时相。两时相和全部切片要归入同一患者。150 是研究总体，实际可读的标签、患者目录及各集合病例数要在取得文件后清点。优先以可核验病例分组的 ACDC 做预算比较。[官方数据库](https://www.creatis.insa-lyon.fr/Challenge/acdc/databases.html)
- Torpey 等在 CVPR 2026 Workshop 的算法 1 中顺序选择新图，对当前图分配交互后加入上下文。其每图交互预算与本项目的累计成本单位不同。这里要检验的是能否回访已纳入支持池的旧标签以改善独立病例表现。保留“只新增且优先选多样病例”与“预算固定各半”作为强对照，比较时匹配总支出、检索器、上下文大小。[Torpey 等原文](https://openaccess.thecvf.com/content/CVPR2026W/PHAROS-AIF-MIH/papers/Torpey_Learning_What_To_Ask_For_When_Image_Ordering_for_In-Context_CVPRW_2026_paper.pdf)
